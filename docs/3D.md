# Star2D 3D mode (branch `3d`)

Design notes for the 3D scene type. 2D scenes are untouched: everything 3D is opt-in per scene.

## Principles
- **One engine, two scene kinds.** A scene has a `Scene Type` property (`2D` default, `3D`). A 3D scene is still a
  `StageImp`: same lifecycle, scene switching, scripts, events, variables, sounds, UIHolder, behaviors. On top of the 2D
  stages it owns a `World3D` (`com.star4droid.template.d3`) that renders first; the 2D GameStage/UiStage draw on top
  (HUD, joysticks, UIHolder screens).
- **3D elements are PlayerItems.** Each 3D element is an `Actor` (a 0-size proxy for name/visibility/children) that
  implements `PlayerItem`, so `findItem`, scripts, element events (onClick via ray picking, OnBodyUpdate, collisions)
  and generic blocks keep working. The 3D state (transform, model instance, bullet body) lives in `Object3D`.
- **Generated code, same pattern as 2D.** New definition classes in `ElementDefs` (`Object3DDef`, `Light3DDef`,
  `Camera3DDef`, `CameraViewDef`) with public `float/String/boolean` fields; `CodeGenerator` emits them like every
  other element.
- **Performance first.** Default renderer is the fast libGDX default shader (vertex lighting off/on per quality),
  frustum culling, distance culling, shared meshes per primitive, merged static batches, optional shadows. PBR / Toon /
  Unlit / Flat / Vertex-lit are optional lighting modes (scene property `Render Mode`).
- **Physics:** Bullet (`gdx-bullet`), only initialised when a 3D scene has physical elements; the exporter drops
  `libgdx-bullet.so` from APKs of projects with no 3D physics.
- **glTF/GLB** models (with skeletal / node animations) through `gdx-gltf`; animations are played, blended, paused and
  stopped from blocks. FBX: planned later.

## Element types
| TYPE        | Def              | What |
|-------------|------------------|------|
| `OBJ3D`     | `Object3DDef`    | Primitive (`CUBE SPHERE CYLINDER CAPSULE CONE PLANE TORUS RAMP STAIRS PYRAMID TERRAIN WATER`) or `MODEL` (glTF/GLB path). Transform, material, physics, rendering, LOD, animation. |
| `LIGHT3D`   | `Light3DDef`     | `DIRECTIONAL POINT SPOT` (+ ambient/sky on the scene). Color, intensity, range, cone, shadows, flicker. |
| `CAMERA3D`  | `Camera3DDef`    | Perspective/orthographic camera; `Active` = main camera; follow/orbit settings. Can feed a CAMERAVIEW. |
| `CAMERAVIEW`| `CameraViewDef`  | 2D element (both scene kinds) that shows what a camera (2D CAMERA or CAMERA3D) sees, live, with zoom; optional touch pass-through. |

## Scene properties (3D)
`Scene Type`, `Render Mode` (SIMPLE, VERTEX, PBR, TOON, UNLIT, FLAT), `Lighting Preset` (DAY, SUNSET, NIGHT, OVERCAST,
STUDIO, HORROR, CUSTOM), `Ambient Color`, `Ambient Intensity`, `Sky` (COLOR, GRADIENT, IMAGE), `Sky Top`, `Sky Bottom`,
`Sky Image`, `Fog`, `Fog Color`, `Fog Near`, `Fog Far`, `Gravity 3D` (x,y,z), `Shadows`, `Shadow Quality`,
`Quality` (LOW, MEDIUM, HIGH, ULTRA, CUSTOM), `Render Scale`, `View Distance`, `MSAA`, `Post Effect`.

## Graphics quality
`Graphics3D` holds the active level; scenes read it, the game can change it at runtime (blocks + a ready-made
settings UI). Editor viewport has its own quality setting (Settings → 3D).

## Units
1 unit = 1 meter. Y is up. Editor shows meters; rotations in degrees (Euler XYZ).
