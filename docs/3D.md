# Star2D 3D mode (branch `3d`)

Design notes for the 3D scene type. 2D scenes are untouched: everything 3D is opt-in per scene.

## Principles
- **One engine, two scene kinds.** A scene has a `Scene Type` property (`2D` default, `3D`). A 3D scene is still a
  `StageImp`: same lifecycle, scene switching, scripts, events, variables, sounds, UIHolder, behaviors. On top of the 2D
  stages it owns a `World3D` (`com.star4droid.template.d3`) that renders first; the 2D GameStage/UiStage draw on top
  (HUD, joysticks, UIHolder screens).
- **3D elements are PlayerItems.** Each 3D element is an `Actor` (a 0-size proxy for name/visibility/children) that
  implements `PlayerItem`, so `findItem`, scripts, element events (onClick via ray picking, OnBodyUpdate, collisions)
  and generic blocks keep working. The 3D state (transform, model instance, bullet body) lives in `Object3D`.
- **Generated code, same pattern as 2D.** New definition classes in `ElementDefs` (`Object3DDef`, `Light3DDef`,
  `Camera3DDef`, `CameraViewDef`) with public `float/String/boolean` fields; `CodeGenerator` emits them like every
  other element.
- **Performance first.** Default renderer is the fast libGDX default shader (vertex lighting off/on per quality),
  frustum culling, distance culling, shared meshes per primitive, no per-frame work for Static Object scenery, optional shadows. PBR / Toon /
  Unlit / Flat / Vertex-lit are optional lighting modes (scene property `Render Mode`).
- **Physics:** Bullet (`gdx-bullet`), only initialised when a 3D scene has physical elements; the exporter drops
  `libgdx-bullet.so` from APKs of projects with no 3D physics.
- **glTF/GLB** models (with skeletal / node animations) through `gdx-gltf`; animations are played, blended, paused and
  stopped from blocks. **Wavefront OBJ** (`.obj` + `.mtl` + pictures, libGDX `ObjLoader`: `Kd` diffuse color and `map_Kd`
  texture; a file that only switches `usemtl` gets one group per material). FBX: planned later.
- Model loading (`Assets3D`): one cache per project file, shared by every element that shows it. A model whose file
  changed is read again (date + size); the old copy is NOT freed while elements may still draw it (freeing it made the
  editor flicker / crash). Load errors are logged (`Star2D-3D`) and the element shows a placeholder box. Meshes without
  normals get smooth normals (else the lit shaders drew them black); glTF base color factor / emissive are copied to the
  default shader's attributes (base color texture = diffuse texture, vertex colors used as is).
- Drawing is fail-safe (`World3D.drawSafely`): if a batch flush throws, the batch is closed by hand and the element that
  breaks it is found and shown as a box, instead of leaving the batch open (only the sky, every frame).

## Element types
| TYPE        | Def              | What |
|-------------|------------------|------|
| `OBJ3D`     | `Object3DDef`    | Primitive (`CUBE SPHERE CYLINDER CAPSULE CONE PLANE TORUS RAMP STAIRS PYRAMID TERRAIN WATER`) or `MODEL` (glTF/GLB path). Transform, material, physics, rendering, LOD, animation. |
| `LIGHT3D`   | `Light3DDef`     | `DIRECTIONAL POINT SPOT` (+ ambient/sky on the scene). Color, intensity, range, cone, shadows, flicker. |
| `CAMERA3D`  | `Camera3DDef`    | Perspective/orthographic camera; `Active` = main camera; follow/orbit settings. Can feed a CAMERAVIEW. |
| `CAMERAVIEW`| `CameraViewDef`  | 2D element (both scene kinds) that shows what a camera (2D CAMERA or CAMERA3D) sees, live, with zoom; optional touch pass-through. |

## Scene properties (3D)
`Scene Type`, `Render Mode` (SIMPLE, VERTEX, PBR, TOON, UNLIT, FLAT), `Lighting Preset` (DAY, SUNSET, NIGHT, OVERCAST,
STUDIO, HORROR, CUSTOM), `Ambient Color`, `Ambient Intensity`, `Sky` (COLOR, GRADIENT, IMAGE), `Sky Top`, `Sky Bottom`,
`Sky Image`, `Fog`, `Fog Color`, `Fog Near`, `Fog Far`, `Gravity 3D` (x,y,z), `Shadows`, `Shadow Quality`,
`Quality` (LOW, MEDIUM, HIGH, ULTRA, CUSTOM), `Render Scale`, `View Distance`, `MSAA`, `Post Effect`.

## Graphics quality
`Quality3D` holds the active level; scenes read it, the game can change it at runtime (3D Graphics blocks); the player choice is saved.
The editor viewport has its own quality (3D scene settings → Editor quality).

## Units
1 unit = 1 meter. Y is up. Editor shows meters; rotations in degrees (Euler XYZ).

## Editor
- New scene → choose **3D scene**: the config gets `sceneType: 3D` and the scene starts with a ground, a cube and a camera.
- One finger on empty space orbits, two fingers pan and zoom, a tap selects, a double tap focuses.
- The rail tools Move / Resize / Rotate show arrows / boxes / rings on the selected element; the center square moves on the ground.
- The **3D view** rail button opens an icon grid: perspective / top / front / side, focus, 2D layer, 3D behind 2D, snap,
  animations, grid, colliders, local axes, scene settings (toggles stay open and show their state).
- The **layer** rail button (cube = 3D world, screen = 2D layer) switches what is edited. The 2D layer is a normal 2D
  canvas (background, grid, scene frame) unless "3D behind 2D" is on.
- **Add** (+) in a 3D scene starts with *Import 3D models*: pick .glb / .gltf / .obj files together with their parts
  (.bin, .mtl, pictures; multi-select), or *Import a model folder* (sub folders kept, so relative names in .mtl / .gltf
  still work). They are copied to the project's `models` folder (folder import: `models/<folder>/...`, model referred to
  as `/<folder>/name.obj`) and a MODEL element is added for each model file. Parts keep their exact names; texture names
  with spaces are not supported by the OBJ loader. The export zips the whole `models` folder.
- Editor: every 3D object of the viewport belongs to an element; objects left without one are dropped each frame
  (`Editor3D.pruneGhosts`). The default plane / cube / camera of a new 3D scene are added after the scene has loaded
  (`loadFromPath` marks the editor as loading at once, so `whenLoaded` waits).
- The 2D layer (HUD, buttons) is hidden while the 3D world is edited.
- Depth: 24-bit (also in the scaled frame buffer), the editor's near plane follows the zoom, the shadow depth has a bias.
- The selected element's collider is drawn in green (off in the 3D view menu / scene settings). Properties → Physics 3D →
  **Edit collider** puts round handles on the collider sides: dragging one moves that side (box: the opposite side stays,
  sphere / capsule / cylinder / cone: radius and height), stored in Collider Scale / Offset, with undo.
- Properties only lists what the element uses: Water for Mesh WATER, Terrain for TERRAIN, Model / Animation for MODEL,
  Steps for STAIRS, Detail for round shapes, body settings only with a Body, cone settings only for SPOT lights, Ortho
  Size only for orthographic cameras; the panel rebuilds when Mesh / Light Kind / Orthographic / Body change.
- Shadows use a depth bias (polygon offset) and a texel-snapped shadow area: no stripes ("shadow acne") while the camera turns.
- The light button opens the 3D scene settings in 3D scenes (render mode, lighting preset, sky, sun, fog, gravity, quality, screen effect).
- HUD / buttons / UI holders live in the 2D layer on top of the 3D picture (edit them with "Switch 3D world / 2D layer").

## Export
`ExportThread.stripNatives` leaves out `libgdx-bullet.so` when the project has no 3D scene, and the x86 libraries when
"Phones only (ARM)" is checked. `tools/make_template.py` also puts the Bullet and gdx-gltf classes into `java/game.zip`
(class path of the on-phone compiler) so scripts may use them.

## Blocks (2D / 3D filter)
- Every block definition has `dims` (`SceneDims.D2`, `D3`, `BOTH`): built-in DSL / extra blocks get it from
  `BlockCatalog.defaultDims` (2D-only categories: Camera, BodyModify, bodyControl, bodyBooleans, Joints, Motion, Physics;
  2D-only titles in shared categories: setsplits, ifCollision, setGravity, setTint, setOpacity, flipX, bringToFront,
  sendToBack, setAnimation, removeAnimation; `destroy`/`destroyAfter` stay BOTH); value blocks from
  `defaultReporterDims` (groups PlayerItem, Box2D Body and the 2D element / touch / camera values are 2D).
- User libraries (`Nodes/nodes.json`, `Nodes/blocks.json`): `"dims"` on a block or on its section (missing = BOTH, so old
  files keep working). The block creator has a 2D / 3D / Both selector; `define_blocks` takes `dims` (category + block).
- The block editor reads the scene of the event path (`Events/<scene>/...`) and `configs/<scene>.json` `sceneType`
  (`SceneDims.modeOfEventPath`) and calls `BlockCatalog.setSceneMode`; `BlockCatalog.isVisible` hides blocks / value
  blocks of the other type and empty categories disappear. `block_catalog` (AI) filters the same way (`all:true` = both).
- The 3D blocks live in `ui/blocks/Blocks3D.java` (12 categories: 3D Motion, Physics, Looks, Animation, Camera,
  Lights & Sky, Effects & Shaders, Graphics quality, Water & Terrain, Objects, Sound, and Inventory for both). They call
  `d3.B3` / `d3.B3x` fully qualified (Java 7). List fields (`mode(followMode)`...) offer chips from
  `BlockCatalog.choices`; `code(glsl)` fields are edited on several lines and stored escaped as a Java string;
  `model(model)` / `shader(shader)` fields browse the models / shaders folders.
- Test: `python3 tools/test_blocks3d.py` (texts, slot counts, Java 7, filter, compiles every 3D block with its defaults
  against the template classes, translations present in the 6 languages).
